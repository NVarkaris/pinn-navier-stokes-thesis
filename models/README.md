# Model Checkpoints

This directory is used for model checkpoints generated by the PINN training scripts.

Pre-trained model checkpoints are intentionally not included in the repository.

All models are generated locally by running the corresponding training scripts.


## Model generation

The main stage scripts can save trained PyTorch checkpoints in this directory when checkpoint saving is enabled.

The exact checkpoint filename depends on the stage and, for inverse problems, on the selected experiment configuration.

Generated checkpoint files use the `.pt` extension.


## Stage 1 and Stage 2

Stages 1 and 2 can generate checkpoints for their stationary forward and inverse PINN models.

Stage 2 checkpoint names depend on the selected inverse-problem configuration.

Detailed information is provided in:

`stage1_stationary_forward/README.md`

and:

`stage2_stationary_inverse/README.md`


## Stage 3

Training Stage 3 generates the forward pulsatile-flow checkpoint:

`models/stage3_forward_model.pt`

Run:

`python stage3_pulsatile_forward/NS_xy_stage3.py`

This checkpoint is used by:

- the Stage 3 pressure-animation script
- Stage 4 experiments that use transfer learning

Therefore, when starting from a fresh clone of the repository, Stage 3 must first be trained before either of these operations can be performed.

The Stage 3 checkpoint is not provided as a pre-trained file.


## Stage 4

Stage 4 checkpoints are generated according to the selected inverse-problem configuration.

Their general naming format is:

`models/stage4_{RUN_NAME}_model.pt`

The run name identifies the main experiment settings, including the inverse-problem family, transfer-learning configuration, training schedule, observation setup, and inverse-parameter initialization.

Run Stage 4 using:

`python stage4_pulsatile_inverse/NS_xy_stage4.py`

When:

`USE_TRANSFER_LEARNING = True`

the following locally generated Stage 3 checkpoint must already exist:

`models/stage3_forward_model.pt`

When transfer learning is disabled, Stage 4 does not require a Stage 3 checkpoint.


## External thesis figures

The standalone plotting scripts do not train models.

They load checkpoints generated by the corresponding thesis experiments.

Therefore, the required Stage 4 experiments must first be reproduced locally before the associated external figures can be generated.

This applies to the scripts for:

- Figure 23
- Figure 25
- Figure 26
- Figure 27

`models/stage4_F2_TL_adam700_300_300_300_lbfgs500_sp1_x2_y2_tm61_A0init8_Tinit0p8_model.pt`

This checkpoint is generated by running the corresponding Stage 4 configuration and is not included in the repository.

Detailed reproduction instructions are available in:

`stage4_pulsatile_inverse/README.md`


## Fresh repository workflow

A fresh clone of the repository does not contain trained model checkpoints.

For workflows that use transfer learning, the recommended order is:

1. Train Stage 3 to generate `models/stage3_forward_model.pt`.
2. Configure and train the desired Stage 4 experiment.
3. Run any external plotting scripts whose required checkpoints have been generated.

Stages 1 and 2 can be run independently and do not require the Stage 3 checkpoint.


## Checkpoint reproducibility

The training scripts support fixed random seeds for reproducibility.

The fixed seed used in the final thesis implementation is:

`189869491`

A fixed seed improves reproducibility but does not guarantee bitwise-identical checkpoints across different hardware, PyTorch versions, CUDA versions, or numerical environments.

Small numerical differences between independently trained models can therefore occur.


## Repository policy

Generated `.pt` checkpoint files are intentionally excluded from version control.

The `models/` directory contains this `README.md` in the repository, while trained checkpoints are created locally when the corresponding experiments are executed.

This keeps the repository focused on the source code, reference data, and reproducible training procedure rather than distributing pre-trained model states.
