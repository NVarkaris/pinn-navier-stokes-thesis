## Repository Overview

The repository focuses on Physics-Informed Neural Networks (PINNs) for forward and inverse incompressible Navier-Stokes problems.

The work progresses from a stationary forward problem to progressively more challenging inverse and time-dependent problems.

The implementation is organized into four stages:

1. Stationary forward problem
2. Stationary inverse problem
3. Pulsatile forward problem
4. Pulsatile inverse problem

The final stage investigates the identification of unknown parameters of a time-dependent inlet-pressure boundary condition using sparse pressure observations, transfer learning, and progressive time-window training.


## Problem overview

The flow is considered in a two-dimensional rectangular channel and is governed by the incompressible Navier-Stokes equations.

The PINNs predict the velocity and pressure fields while enforcing the governing equations and appropriate initial and boundary conditions through the loss function and, in the pulsatile stages, through hard constraints.

COMSOL Multiphysics solutions are used as reference data for:

- evaluation
- sparse inverse-problem observations
- plotting and comparison

The COMSOL fields are not used as full-field supervised training data.

## Stage 1 - Stationary forward problem

Stage 1 solves a stationary incompressible Navier-Stokes forward problem.

The neural network receives the non-dimensional spatial coordinates and predicts:

`(y*, x*) -> (u_y*, u_x*, p*)`

The inlet pressure and outlet pressure are prescribed.

The PINN is trained using:

- continuity residual
- x-momentum residual
- y-momentum residual
- inlet boundary conditions
- outlet boundary conditions
- upper-wall no-slip condition
- lower-wall no-slip condition

Training is performed using Adam followed by L-BFGS.

Run from the repository root:

`python stage1_stationary_forward/NS_xy_stage1.py`

Detailed information is available in:

`stage1_stationary_forward/README.md`


## Stage 2 - Stationary inverse problem

Stage 2 extends the stationary problem to an inverse formulation.

The inlet pressure becomes a trainable parameter and is inferred from sparse pressure measurements along the channel centerline.

The neural-network mapping remains:

`(y*, x*) -> (u_y*, u_x*, p*)`

The inverse parameter is optimized simultaneously with the neural-network parameters.

Several observation scenarios are included using different numbers of sparse pressure measurements.

Run:

`python stage2_stationary_inverse/NS_xy_stage2.py`

Stage 2 also includes a standalone plotting script for reproducing thesis Figures 13 and 14:

`python stage2_stationary_inverse/plot_stage2_figures_13_14.py`

Figures generated by individual Stage 2 runs are stored under:

`stage2_stationary_inverse/figures/`

Standalone thesis figures are stored under:

`stage2_stationary_inverse/external_figures/`

Detailed information is available in:

`stage2_stationary_inverse/README.md`


## Stage 3 - Pulsatile forward problem

Stage 3 introduces time dependence.

The neural network receives the non-dimensional spatial coordinates and time and predicts:

`(y*, x*, t*) -> (u_y*, u_x*, p*)`

The inlet pressure is prescribed as:

`p_in(t) = A0 + A1 sin(2 * pi * t / T)`

with the reference parameters:

- `A0 = 10 Pa`
- `A1 = 5 Pa`
- `T = 0.5 s`

The wall no-slip boundary conditions and inlet/outlet pressure conditions are imposed through hard constraints.

Training uses a progressive time-window curriculum:

`[0,1] s -> [0,2] s -> [0,3] s`

with Adam training performed sequentially across the time windows and a final L-BFGS optimization on the full time interval.

Run:

`python stage3_pulsatile_forward/NS_xy_stage3.py`

The trained forward checkpoint is stored at:

`models/stage3_forward_model.pt`

This checkpoint can subsequently be used for transfer learning in Stage 4.

Stage 3 also includes a pressure-field animation script:

`python stage3_pulsatile_forward/stage3_pressure_animation.py`

The generated animation is stored under:

`stage3_pulsatile_forward/animations/`

Detailed information is available in:

`stage3_pulsatile_forward/README.md`


## Stage 4 - Pulsatile inverse problem

Stage 4 extends the pulsatile problem to an inverse formulation.

The inlet pressure remains:

`p_in(t) = A0 + A1 sin(2 * pi * t / T)`

but one or more pressure parameters are inferred from sparse pressure observations.

Three inverse-problem families are implemented:

| Family | A0        | A1        | T         |
| ------ | --------- | --------- | --------- |
| F1     | Trainable | Trainable | Known     |
| F2     | Trainable | Known     | Trainable |
| F3     | Trainable | Trainable | Trainable |

Stage 4 supports:

- sparse pressure observations
- different numbers of temporal observations
- multiple spatial observation locations
- transfer learning from Stage 3
- training with or without transfer learning
- single-window training
- progressive time-window training
- configurable Adam training schedules
- L-BFGS refinement
- simultaneous inference of multiple physical parameters

Run:

`python stage4_pulsatile_inverse/NS_xy_stage4.py`

Detailed information about all experiment families, observation scenarios, training profiles, and configurations is available in:

`stage4_pulsatile_inverse/README.md`


## Progressive time-window training

A central methodological component of the pulsatile problems is progressive time-window training.

Instead of immediately training over the complete time interval, the PINN is first optimized on a shorter temporal domain.

The interval is then progressively expanded while preserving:

- neural-network parameters
- optimizer state where appropriate
- inferred inverse parameters

For example, Stage 4 experiments use schedules such as:

`[0,0.5] s -> [0,1] s -> [0,2] s -> [0,3] s`

This continuation strategy is particularly important for identifying the inlet-pressure period.

Direct optimization over the entire time interval can lead to poor parameter recovery because period errors accumulate as phase errors over time and produce a more difficult optimization landscape.

Progressive training first moves the inferred period toward the correct region using a simpler short-time problem and subsequently extends the solution to the full time interval.


## Transfer learning

Stage 4 can initialize its neural-network layers from the trained Stage 3 forward model.

The required checkpoint is:

`models/stage3_forward_model.pt`

When transfer learning is enabled:

- the neural-network weights and biases are loaded from Stage 3
- the inverse parameters are not transferred
- the Stage 4 inverse parameters use their own configured initial values

This allows the inverse problem to begin from a network that already represents the underlying pulsatile-flow dynamics.

## Figure 25 and the period-loss landscape

Figure 25 evaluates the pressure-data loss as a function of the inlet-pressure period `T`.

The final trained state of the successful Stage 4 progressive-window experiment is loaded and frozen.

The neural-network parameters and the remaining inverse parameters are kept fixed while only `T` is varied.

The network is not retrained for each tested value of `T`.

The data-loss landscape is evaluated for:

- the short interval `[0,0.5] s`
- the full interval `[0,3] s`

The short interval exhibits a clear minimum around the true period.

On the full interval, the correct minimum becomes significantly narrower while regions of smaller gradient and local variations appear away from the global minimum.

This analysis supports the use of progressive time-window training for period identification.

## Reproducibility

The implementations support deterministic seed configuration.

The fixed seed used for the final thesis implementation is:

`189869491`

When fixed-seed mode is enabled, the seed is applied to:

- Python
- NumPy
- PyTorch

The seed used for each run is printed and stored in the generated outputs where applicable.

A fixed random seed improves reproducibility but does not guarantee bitwise-identical results across different:

- hardware
- CUDA versions
- PyTorch versions
- numerical environments

Small numerical differences between runs can therefore occur even when the same configuration and seed are used.


## Evaluation

PINN predictions are evaluated against the corresponding COMSOL reference solution.

The reported global metrics include:

- RMSE
- L2 error
- Relative L2 error

The primary evaluated fields are:

- streamwise velocity `u_x`
- transverse velocity `u_y`
- velocity magnitude `|v|`
- pressure `p`

Because the reference transverse velocity can be close to zero, its relative L2 error is not generally interpreted numerically.

Additional diagnostics include:

- boundary-condition checks
- inverse-parameter errors
- per-time-slice field errors
- loss evolution
- learning-rate evolution
- training-time information

`stationary forward -> stationary inverse -> pulsatile forward -> pulsatile inverse`

The same general neural-network representation is progressively extended to include:

- sparse observations
